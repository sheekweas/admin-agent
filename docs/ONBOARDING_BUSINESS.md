# Подключение нового бизнеса (ТЗ §23.1)

Для оператора платформы и владельца бизнеса. Работа в панели подробно описана в
[руководстве пользователя](user-guide/README.md); здесь — порядок действий и параметры подключения каналов.
Обозначения: `<API>` = `PUBLIC_BASE_URL` (например `https://api.example.kz`), `<APP>` = `ADMIN_PANEL_URL`.

## 0. Предварительно (решения бизнеса)

Собрать до начала: название, ниша (`barbershop|beauty|dental|other`), язык клиентов по умолчанию (RU/KK),
филиалы с адресами и часовыми поясами, прайс услуг (RU и KK названия, длительность, цена, буферы), сотрудники и
их графики, кто основной и резервный администратор эскалаций (телефоны, Telegram), тихие часы для звонков,
нужна ли предоплата/подтверждение брони админом, тексты базы знаний (адреса, парковка, правила отмены, оплата).

## 1. Организация, владелец, первый филиал (оператор платформы)

Создание организации доступно только оператору (через CLI на сервере, в API такой операции нет):

```bash
docker compose --env-file deploy/.env.production -f deploy/docker-compose.prod.yml exec api \
  python -m app.cli create-tenant \
    --name "Barber Pro" --owner-email owner@barberpro.kz --owner-name "Айдар Сапаров" \
    --owner-phone +77010000000 --branch "Barber Pro Алматы" --branch-address "Алматы, пр. Абая 10" \
    --timezone Asia/Almaty --niche barbershop --language ru --currency KZT
```

- Вывод — JSON с `tenant_id`, `branch_id`, `owner_user_id`. Если пароль не передан (`--owner-password` или
  переменная `CRM_OWNER_PASSWORD`), он генерируется и показывается **один раз** — передайте владельцу
  защищённым каналом и попросите сменить.
- Команда идемпотентна: повторный запуск с тем же названием и e-mail владельца ничего не меняет
  (`"created": false`). Существующий пользователь (тот же e-mail) привязывается владельцем без смены пароля.
- Действие пишется в журнал аудита (`tenant.create`).

Владелец входит в `<APP>` и дальше всё делает в панели.

## 2. Настройка в панели (владелец)

| Шаг | Где | Что проверить |
|---|---|---|
| Организация и правила | «Настройки» | язык по умолчанию, шаг слота, удержание слота, мин. время до записи, дедлайн отмены, напоминания (24/2 ч), подтверждение брони админом, тихие часы, таймеры эскалации 5/10 мин |
| Филиалы | «Настройки» (блок филиалов) | адрес, **часовой пояс** (Алматы/Астана — `Asia/Almaty`), контакты |
| Услуги | «Услуги» | названия RU и KK, длительность, цена, буферы до/после, ресурс (кресло/кабинет), «опубликована» — AI предлагает только опубликованные |
| Сотрудники и графики | «Сотрудники» | филиал, услуги мастера, недельный график с перерывами, исключения (выходные/отпуск) |
| Команда и роли | «Настройки → Команда и роли» | роли owner/admin/staff/analyst, доступ к филиалам, флаги **основной / резервный** администратор эскалации, телефон в E.164, Telegram chat id (шаг 4), язык интерфейса (на нём звучит IVR) |
| База знаний | «AI и знания» | статьи RU и KK: адреса, режим работы, парковка, оплата, отмена, запреты. AI использует только **опубликованные** статьи; проверить кнопкой проверки ответа (раздел 11 руководства) |
| AI | «AI и знания → Настройки» | тон, запрещённые темы, резервные сообщения RU/KK, разрешать другого мастера/филиал; для стоматологий — `medical_safe_mode` |

## 3. WhatsApp Cloud API (Meta)

Платформенные значения (один раз на сервер, `deploy/.env.production`): `WHATSAPP_MODE=live`,
`WHATSAPP_APP_SECRET` (Meta App → Settings → Basic → App secret), `WHATSAPP_VERIFY_TOKEN` (случайная строка из
`generate-secrets`).

1. **Business Manager** (business.facebook.com): подтвердить компанию (Business Verification), добавить способ
   оплаты для WhatsApp.
2. **Meta for Developers** (developers.facebook.com) → Create App → тип *Business* → добавить продукт **WhatsApp**,
   привязать WhatsApp Business Account (WABA).
3. **Номер**: WhatsApp → API Setup → Add phone number. Номер не должен быть зарегистрирован в приложении
   WhatsApp/WhatsApp Business (иначе удалить там аккаунт). Пройти подтверждение по SMS/звонку, задать
   отображаемое имя (проходит модерацию Meta). Скопировать **Phone number ID**.
4. **Постоянный токен**: Business Settings → Users → System users → создать system user (Admin) → Assign assets:
   приложение и WABA (Full control) → Generate token с правами `whatsapp_business_messaging`,
   `whatsapp_business_management`. Временный токен из API Setup живёт 24 ч — для продакшена не годится.
5. **Вебхук**: App → WhatsApp → Configuration → Webhook:
   - Callback URL: `<API>/v1/webhooks/whatsapp`
   - Verify token: значение `WHATSAPP_VERIFY_TOKEN`
   - Нажать *Verify and save* (сервер отвечает на `hub.challenge`), затем подписаться на поле **messages**.
6. **Панель → «Интеграции → WhatsApp»**: `phone_number_id`, access token (write-only, хранится зашифрованным),
   при отдельном Meta-приложении у бизнеса — его `app_secret`. «Проверить» → статус OK.
7. **Шаблон вне 24-часового окна** (напоминания, подтверждения, ответы админа позже 24 ч после последнего
   сообщения клиента): WhatsApp Manager → Message templates → Create, категория *Utility*, язык RU (и KK при
   необходимости), тело с **одной** переменной, например: `Здравствуйте! {{1}}`. После одобрения Meta указать в
   интеграции `template_name` и `template_language` (например `ru`). Без шаблона такие сообщения не уходят
   (ошибка `OUTSIDE_SERVICE_WINDOW` в «Интеграции → События»).
8. Тест: написать на номер с личного телефона → сообщение в «Чатах», ответ AI.

Ограничения Meta (проверить на дату запуска): лимиты на число новых диалогов в сутки растут с качеством номера;
один номер — одна организация (уникальность `phone_number_id` проверяется системой).

## 4. Telegram (уведомления и эскалации администраторам)

Платформа: `TELEGRAM_MODE=live`, `TELEGRAM_WEBHOOK_SECRET`, публичный `PUBLIC_BASE_URL`.

1. В Telegram открыть **@BotFather** → `/newbot` → имя и username → получить **токен бота**.
   Рекомендуется: `/setjoingroups` → Disable, `/setprivacy` → Enable.
2. Панель → «Интеграции → Telegram»: вставить токен → «Проверить». Сервер сам вызывает `setWebhook` на
   `<API>/v1/webhooks/telegram/<tenant_id>` с секретом арендатора — вручную ничего регистрировать не нужно.
3. Каждый администратор открывает бота и отправляет `/start` → бот отвечает «Ваш Telegram chat id: …».
   Этот id вносится в профиль сотрудника («Настройки → Команда и роли»).
4. Повторно «Проверить» — администратору с chat id придёт тестовое сообщение. Кнопки «Взять» в карточках работают
   только для активных owner/admin этой организации с доступом к филиалу.

## 5. Twilio Voice (звонок админу через 10 минут, AI-звонки)

Платформа: `VOICE_PROVIDER=twilio`; учётные данные можно задать глобально (`TWILIO_*`) или по организации.

1. Аккаунт Twilio, перевести из trial (trial звонит только на подтверждённые номера и добавляет фразу).
2. Купить номер с возможностью **Voice** (наличие казахстанских номеров и требования Regulatory Bundle —
   проверить в консоли, ТЗ §27). Для исходящих звонков в KZ — включить направление в
   Voice → Settings → Geo permissions.
3. Панель → «Интеграции → Звонки»: `phone_number` (номер в E.164 — по нему входящий звонок находит организацию),
   секреты `account_sid`, `auth_token`, `from_number` → «Проверить». Без `auth_token` все Twilio-вебхуки
   отклоняются (проверка `X-Twilio-Signature`).
4. Twilio Console → Phone Numbers → номер → Voice Configuration:
   - *A call comes in*: Webhook, `POST <API>/v1/webhooks/voice/twilio/inbound`
   - *Call status changes*: `POST <API>/v1/webhooks/voice/twilio/status`
   Остальные адреса (`turn`, `dial`, `answer`, `recording`, `gather`) сервер передаёт Twilio сам.
   `PUBLIC_BASE_URL` должен в точности совпадать с адресом в консоли (по нему считается подпись).
5. У основного и резервного администратора — телефон в E.164 и флаги эскалации; тихие часы — «Настройки».
6. Голосовые настройки (`settings.voice`): запись разговоров (выкл. по умолчанию), срок хранения, лимит и окно
   исходящих, голоса RU/KK. У Twilio нет казахского TTS-голоса: казахский текст читает русский голос.
7. Тест — процедура AT-18 в [ACCEPTANCE.md](ACCEPTANCE.md).

## 6. Zapier и внешние системы (исходящие вебхуки)

Панель → «Интеграции → Вебхуки»: URL (только https, не внутренние адреса), события (`booking.created`,
`booking.cancelled`, `payment.confirmed`, `lead.created`, … или `*`), флаг `include_pii` (по умолчанию персональные
данные вырезаются). Секрет подписи показывается **один раз** при создании. Получатель проверяет
`X-CRM-Signature = sha256=HMAC(secret, "<X-CRM-Timestamp>." + body)`, окно 5 минут и дедуплицирует по
`X-CRM-Delivery` (пример кода — [SECURITY.md](SECURITY.md) §2). В Zapier: триггер *Webhooks by Zapier → Catch Hook*,
его URL вставить в подписку; «Проверить» отправляет событие `ping`.

## 7. Чек-лист запуска (go-live)

- [ ] Организация создана, владелец сменил пароль; команда приглашена, роли и доступ к филиалам проверены.
- [ ] Филиалы с верными часовыми поясами; услуги опубликованы, RU и KK названия заполнены; у мастеров есть услуги и графики на 2+ недели вперёд.
- [ ] Основной и резервный администратор: телефон, Telegram chat id, тестовое сообщение получено.
- [ ] База знаний: опубликованы статьи RU и KK; проверка ответа AI даёт верные ответы на 10 типовых вопросов без выдумок; на вопрос «вне базы» AI честно эскалирует.
- [ ] WhatsApp: «Проверить» = OK, тестовая переписка RU и KK → запись создана в календаре → подтверждение клиенту → карточка в Telegram.
- [ ] Шаблон для сообщений вне 24 ч одобрен Meta и указан в интеграции.
- [ ] Эскалация: задача без ответа → повтор через 5 мин → звонок через 10 мин (или осознанно `calls_enabled=false`).
- [ ] Отмена клиентом через WhatsApp освобождает слот; напоминания запланированы.
- [ ] Согласия и тексты политики конфиденциальности согласованы (см. [THIRD_PARTY.md](THIRD_PARTY.md) §5).
- [ ] Оператор: бэкап ночью прошёл, алерты настроены ([OPERATIONS.md](OPERATIONS.md)); `AI_GLOBALLY_DISABLED=false`, `LLM_PROVIDER=anthropic`, mock-режимы выключены.
- [ ] Администраторы прочитали [руководство пользователя](user-guide/README.md) (разделы 5, 6, 13) и знают, как перехватить диалог и выключить AI для организации («AI и знания → Настройки»).
